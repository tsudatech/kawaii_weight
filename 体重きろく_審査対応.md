# たいかん！ — 審査対応メモ（Guideline 2.1 Information Needed・4.3(a) Spam）

作成日: 2026年10月29日（2026年11月4日に新しい名前と機能へ更新）
対象: iOS版「たいかん！」／英語名「Taikan!」（`jp.jntech.kawaii-taiju-kanri` / v1.0）

新規アプリの審査でよく来る「Guideline 2.1 - Information Needed」への返信文と、添付する画面収録の撮り方、「Guideline 4.3(a) - Spam」への返信文（§3）をまとめています。

- **返信文**（§1）は、App Store Connect の返信欄にそのまま貼れます。
- **同じ文**を「App Review に関する情報」の **メモ（Notes）** 欄にも入れておいてください（次回以降の審査のため、と指示されています）。メモ欄は4000文字までで、この文は約3,980文字です（ほかに書き足すときは、どこかを削ってください）。メモ欄にはこの §1 の文を入れます（`体重きろく_AppStore掲載情報.md` §7 の審査メモは、字数の上限のため入れません）。
- 先回りして**最初の提出時からメモ欄に入れておく**と、この問い合わせ自体が来にくくなります。

> **撮る前に必ず確認**：いまのプロジェクトは **iOS 18.0 以降**向けです（`IPHONEOS_DEPLOYMENT_TARGET = 18.0`。アプリ本体とウィジェットの両方）。
> 審査は「最新の OS の実機」での収録を求めているので、**撮影に使う iPhone を最新の iOS（27 系）に上げてから**撮ってください。
> 対応 iOS は 18.0 まで下げてありますが、収録は最新の iOS で撮ります。
> いまの動画は iOS 26.6.2 で撮っています。27 系に上げずにこの動画を使うと、最新の OS ではないと指摘される可能性があります。

### 最初の提出時に前もって入れておく場合

「App Review に関する情報」に、文と動画の両方を入れてから審査に出します。

1. **メモ（Notes）** 欄に、下の文を貼る（§1 の返信文の冒頭を、問い合わせ前の言い方に変えたもの）
2. **添付ファイル（Attachment）** 欄に、§2 の手順で撮った画面収録の動画を入れる
3. 保存してから「審査へ提出」

```
Hello App Review Team,

Thank you for reviewing Taikan! (Japanese name: たいかん！). To help with the review, here is information about the app.

1. Screen recording
A screen recording is attached to the App Review Information section. It was captured on a physical iPhone 16 running iOS 26.6.2. It begins with launching the app and shows the typical flow: first-launch setup, tips, logging weights, the character's reaction, Bounce-back watch, treat days, hiding the numbers, share cards, the Graph tab with calendar and day details, the Buddy tab, and Settings.
The app has no account, login, shared user-generated content or paid content, so those flows do not exist.

2. Purpose and target audience
Taikan! is a daily weight log with a character. Its face changes with the user's weight compared with the average of the previous 7 days. After a gain, the character watches with the user until they are back to their usual weight, and users can hide the numbers on days they would rather not see them.
It is for adults and teens who have struggled to keep a weight log because a heavier day feels discouraging. No account is needed, and logs stay on the device unless the user turns on iCloud Backup.

3. How to access the main features
No login, credentials or sample files are required. Everything is available right after launch.
- First launch: a 4-step setup, then short tips on each tab.
- Home: enter today's weight with the - and + buttons, optionally choose tags, and tap "Log it". The character reacts, and "Today's mood" lets the user choose a different face. "+ Log a past day" and "Edit log" open a sheet for weight, body fat, tags and a note.
- Graph tab: graphs, stats, BMI and a calendar. Tapping a logged day opens its details.
- Bounce-back watch: log a gain tagged "Night out" or "Ate out" and a cloud card appears on Home; it clears when the weight returns.
- Treat days: after logging today, tap "Declare" on the Home card to mark tomorrow as a treat day.
- Share: "Share" on Home opens an image card. The weight appears only if the user chooses to show it.
- Buddy tab: name the character, the friendship level, clouds cleared, reward medals and the face collection.
- Settings tab: height and goal, how faces are judged, reminders, Weight Guess (a game, off by default), Hide my weight, guides for widgets and Siri, iCloud Backup, CSV export, and erasing all data.
- Home Screen and Lock Screen widgets and a Log weight control can be added from the system galleries. Siri: "Log my weight in Taikan!" (Siri then asks how much).

4. External services
- Google AdMob for banner and occasional interstitial ads, and Google UMP for ad consent where required. App Tracking Transparency is requested before ads are personalized; the app works fully if declined. Weight logs are never shared with Google.
- Apple iCloud key-value storage, only when the user turns on iCloud Backup in Settings, to sync logs between the user's own devices.
- Local notifications for the daily reminder, which can be turned off.
- WidgetKit and App Intents for widgets, the control, Siri and Shortcuts.
The app itself runs entirely on the device. It has no developer server, analytics, authentication service, payment processor or AI service, and it does not use HealthKit.

5. Regional differences
The app functions consistently in all regions, except that the UMP consent form appears where legally required (such as the EEA, the UK and Switzerland). The app is available in Japanese and English and follows the device language.

6. Regulated industry or third-party material
Not applicable. The app is a personal wellness log, not a medical device, and does not provide medical diagnosis or advice; BMI is shown for reference only. All characters and artwork were created for this app. The fonts Zen Maru Gothic and Baloo 2 are used under the SIL Open Font License.

If you need anything else, please let us know.

Best regards,
Jun Tsuda
```

## 2. 画面収録の撮り方

### 2-1. 準備

| 項目 | 内容 |
|---|---|
| 端末 | **実機の iPhone**（シミュレータは不可）。その時点の**最新の iOS** に上げてから撮る（いまの対応 iOS は 18.0 以降） |
| ビルド | **審査に出すのと同じ内容のビルド**を使う。手で撮るときは TestFlight で入れ、自動で撮るときは §2-4 の Release ビルドを使う（Debug 版は、テスト広告の「Test mode」や、せっていの「デバッグ」の欄が映るので使わない） |
| 状態 | アプリを**一度削除してから**入れ直す（はじめの設定と各タブの案内から撮るため）。**削除すると端末の記録が消えます**。iCloud バックアップをオンにしている場合は、入れ直したあとオンにすると記録が戻るので、撮影中はオンにしないでおく |
| 言語 | iPhone の言語を**英語**にしておく（審査担当が読みやすい）。日本語のままでも問題はない |
| 通知など | おやすみモード（集中モード）をオンにして、撮影中のほかのアプリの通知を止める |
| 画面収録 | 「設定」→「コントロールセンター」に「画面収録」を追加しておく |

> **広告について**：AdMob の審査が通るまでは広告が返ってこないので、実機の収録には**広告が出ないことがあります**（そのときはバナーの場所も空きません）。広告が出ても、**広告は押さないでください**。全画面広告は、3回記録したあとのタブの切りかえでしか出ない作りです。

### 2-2. 撮る順番（目安 3〜5分）

審査に必要な最低限の流れです。コントロールセンターから画面収録を始め、iPhone のホーム画面が映った状態から撮ります。**必ずアプリの起動から**始めてください。

| # | 操作 | 映すもの |
|---|---|---|
| 1 | iPhone のホーム画面でアプリのアイコンをタップ | 起動 |
| 2 | はじめの設定：「Get started」→「Next」→「Turn on reminders」→ 通知の許可で「Allow」→「Log today's weight」 | はじめの設定・通知の許可 |
| 3 | ホームの案内を最後まで進める → トラッキング許可（ATT）で「Ask App Not to Track」 | 案内・許可を求める流れ。EEA などでは、その前に広告の同意フォームが出る |
| 4 | 「+ Log a past day」→ ‹ で2日前にして「Log this day」→ ごほうびのお祝いを閉じる | 記録シート・はじめてのごほうび |
| 5 | もう一度「+ Log a past day」→ ＋ で 0.5kg 増やし、タグ「Night out」→「Log this day」 → ホームを下へスクロール | **もどるまで見守り**（雲のカード） |
| 6 | タブ「Settings」→ 案内を進める →「Hide my weight」をオン → タブ「Home」で確認 → もどってオフ → 下へスクロール | **見ないモード**・せっていの中身 |
| 7 | タブ「Graph」→ 案内を進める → 下へスクロールしてカレンダーの記録のある日をタップ → 日の詳細 → 戻る | グラフ・カレンダー・日の詳細 |
| 8 | タブ「Buddy」→ 案内を進める → 下へスクロール | おへや・なかよし度・はらしたもやもや |
| 9 | タブ「Home」→ 体重を − で 0.4kg 減らし「Log it」 | **もやもやがはれる**（紙ふぶき）（いちばん大事） |
| 10 | 下へスクロールして「Declare」 | **ごほうびの日せんげん** |
| 11 | 上へもどって「Share」→ カードを見て × で閉じる | シェアカード |
| 12 | 画面収録を止める | — |

**コツ**
- **手順 9 の記録は最後にしてください。** 全画面広告は3回記録したあとのタブの切りかえで出るので、手順 9 のあとはタブを切りかえません。
- 各画面は2〜3秒止めて、何の画面か分かるように映します。
- 「Erase all data」は押さないでください（記録が消え、はじめの設定に戻ります）。
- 撮り直すときは、もう一度アプリを削除して入れ直します（はじめの設定と案内は、1度見ると出ません）。

### 2-3. 提出

1. 写真アプリに保存された動画を、そのまま返信に添付します（サイズが大きすぎるときは、写真アプリの編集で前後の余分を切ります）。
2. 返信欄に §1 の文を貼って送信します。
3. 「App Review に関する情報」のメモ欄にも同じ文を貼って保存します。動画は、メモ欄の下の「添付ファイル」にも入れておくと、次回以降も使えます。

### 2-4. 自動で撮る（UI テスト）

§2-2 の流れを自動で進める UI テストがあります（`kawaii_taiju_kanriUITests/ReviewWalkthroughTests.swift`、スラッシュの ReviewWalkthroughTests と同じ作り）。iPhone の言語が日本語でも英語でも動きます。所要時間は、実機で約5分です（シミュレータでは約3分）。

**テストが進める流れ**は §2-2 と同じです。

- 記録は3回で、3回目はいちばん最後です（全画面広告は3回記録したあとのタブの切りかえで出る作りなので、収録の途中では出ません）。
- **広告は押しません**：バナー（タブバーの上）やタブバーにかかるボタンは、上へスクロールしてから押します。出せないときは押しません。
- 「すべてのデータを消す」は押しません。
- **起動直後に間があきます**：実機では、アイコンをタップしてから最初の操作まで約1分かかりました。白い画面が続いていないか、動画で確かめてください（原因は未確認です）。

**準備**

1. iPhone を Mac につなぎ、ロックを解除しておく（集中モードは §2-1 のとおり）
2. アプリを**削除**してから、**入れ直しておく。開かないこと**（はじめの設定・案内・許可のダイアログから撮るため。**削除すると記録が消えます**）。入っていない状態から実行すると、アイコンがまだなくてタップできず、アイコンを使わない起動になります。入れ直しは次のとおり：
   ```bash
   xcodebuild build -project kawaii_taiju_kanri.xcodeproj -scheme kawaii_taiju_kanri -configuration Release \
     -destination 'id=<iPhone の ID>' -allowProvisioningUpdates -derivedDataPath /tmp/taikan-review
   xcrun devicectl device install app --device <iPhone の ID> /tmp/taikan-review/Build/Products/Release-iphoneos/kawaii_taiju_kanri.app
   ```
   テストのコマンドにも `-derivedDataPath /tmp/taikan-review` を付けると、ビルドしなおしが短くすみます。
3. 1回目の実行で、テスト用のアプリ「kawaii_taiju_kanriUITests-Runner」がホーム画面に入ります。**収録に映らないよう、アプリのアイコンとは別のページ（または App ライブラリだけ）に移しておく**
4. コントロールセンターから画面収録を始めてから、下のコマンドを実行する（アプリがホーム画面の見えるところにあることを確かめてから）

```bash
# 実機（iPhone 16）の ID は xcrun devicectl list devices で確認
xcodebuild test -project kawaii_taiju_kanri.xcodeproj -scheme kawaii_taiju_kanri \
  -configuration Release -parallel-testing-enabled NO \
  -destination 'id=00008140-001E04213E6B001C' -allowProvisioningUpdates \
  -only-testing:kawaii_taiju_kanriUITests/ReviewWalkthroughTests
```

- `-configuration Release`：テスト広告の「Test mode」や、せっていの「デバッグ」の欄を映さないため（シミュレータでは Release でも「Test mode」が出ます）。
- `-parallel-testing-enabled NO`：シミュレータの複製で動かさないため。
- 端末の iOS がアプリの対応 iOS（18.0）より古いと入りません。
- Mac に結果（`TEST SUCCEEDED`）が出たら、画面収録を止めます。テスト中は iPhone に触らないでください。
